# Native directory discovery and topology reads

Research date: 2026-11-12. Scope: delivery ticket [#27](https://github.com/deploymenttheory/go-sdk-activedirectory/issues/27), on `feat/directory-discovery`, starting at SDK commit `ffee945`. The task context confirms that the ticket's only dependency, #9, is closed; the ticket is unblocked. This report records research and proposed contracts, not implementation or new lab evidence. No VMs were accessed or changed.

The inspected dependency is exactly `github.com/deploymenttheory/go-bindings-win32 v0.6.1-0.20261112134443-9f51cb95639f`, as pinned in [go.mod](../../go.mod). A newer checkout of that library exists locally, but findings below refer to the pinned module cache. The existing SDK provides explicit-endpoint LDAP, current/explicit Negotiate credentials, and RootDSE; it does not yet provide general searches or these four directory operations. See [client.go](../../client.go), [config.go](../../config.go), [native_api_windows.go](../../native_api_windows.go), and [connection documentation](../connection.md).

## Recommended implementation boundary

Implement DC Locator as a separate operation, and implement directory-object reads over the authenticated LDAP client. A successful locator call returns one advertised candidate; it cannot establish identity lookup, complete DC enumeration, functional levels, all FSMO owners, or trusted-domain-object properties. Microsoft's command contract separates DC Identity, Filter, and DiscoverByService, while its topology protocol derives richer objects from directory metadata. [Get-ADDomainController](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-addomaincontroller?view=windowsserver2025-ps), [MS-ADCAP GetADDomainController](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/3c9b9f1d-655d-43a2-a231-9ba53fdf93b8).

The implementation should reuse the shared paged-search/filter work and connection/TLS work when available. These are engineering seams, not newly asserted GitHub dependencies. All Windows dispatch must use generated `go-bindings-win32` wrappers. PowerShell/RSAT may supply reference evidence only; neither is an SDK runtime dependency. No raw SDK syscalls, remote helper, copied wrapper, or hand-edited generated ABI definition is needed. This follows the [repository runtime contract](../../README.md) and the task's upstream-generator requirement.

DC Filter is an expression-language contract; the cmdlet has no LDAPFilter parameter despite generic parameter-help text suggesting one. A typed Go predicate API can provide an intentional shell-free equivalent, but cannot claim expression parity by accepting only raw LDAP or only one predicate. Class-constrain every lookup, escape literal filter values independently from DN syntax, reject ambiguous results, and preserve the distinction between no result, unsupported identity form, and unreadable/incomplete resolution. The first distinction follows the [DC syntax and description](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-addomaincontroller?view=windowsserver2025-ps); the resolution requirements are in the local behavioral inventory.

## DC Locator: precise request and result contracts

The pinned wrapper is `activedirectory.DsGetDcName(computer, domain *string, guid *win32.GUID, site *string, flags uint32, out **DOMAIN_CONTROLLER_INFOW) uint32`. It dispatches to `NETAPI32!DsGetDcNameW`; nil inputs remain native NULL. `ComputerName` selects the machine processing the locator request, not the LDAP server to retrieve. For the proposed public locator, keep it NULL and process locally; never map `Config.Endpoint.Host` to this argument. The underlying signature has no credential or timeout argument. [Pinned wrapper](https://github.com/deploymenttheory/go-bindings-win32/blob/9f51cb95639f/bindings/win32/networking/activedirectory/activedirectory_functions.go#L1135), [native API](https://learn.microsoft.com/en-us/windows/win32/api/dsgetdc/nf-dsgetdc-dsgetdcnamew).

A NULL domain selects the processing computer's domain, or its forest for GC discovery. DomainGuid is a fallback when name-based discovery fails, not a conjunctive assertion that the named domain has that GUID. The proposed cmdlet-equivalent locator can leave it NULL; identity verification belongs in authenticated reads. [MS-NRPC locator processing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nrpc/fb8e1146-a045-4c31-98d1-c68507ad5620).

Proposed mapping below uses constants already present in the [pinned generated constants](https://github.com/deploymenttheory/go-bindings-win32/blob/9f51cb95639f/bindings/win32/networking/activedirectory/activedirectory_constants.go). Numeric values are input flags, not the different output capability bits.

| SDK criterion | Native flag | Hex value | Contract |
| --- | --- | --- | --- |
| Default AD DC requirement | DS_DIRECTORY_SERVICE_REQUIRED | 0x00000010 | Require directory service |
| DNS result names | DS_RETURN_DNS_NAME | 0x40000000 | DNS names; also implies IP requirement |
| ForceDiscover | DS_FORCE_REDISCOVERY | 0x00000001 | Bypass cached discovery |
| GlobalCatalog | DS_GC_SERVER_REQUIRED | 0x00000040 | Require GC |
| PrimaryDC | DS_PDC_REQUIRED | 0x00000080 | Require PDC |
| KDC | DS_KDC_REQUIRED | 0x00000400 | Require KDC |
| TimeService | DS_TIMESERV_REQUIRED | 0x00000800 | Require time service |
| Writable | DS_WRITABLE_REQUIRED | 0x00001000 | Require writable DC |
| ReliableTimeService | DS_GOOD_TIMESERV_PREFERRED | 0x00002000 | Preference, with time-server fallback |
| AvoidSelf | DS_AVOID_SELF | 0x00004000 | Applies when locator processor is a DC |
| Explicit flat domain name | DS_IS_FLAT_NAME | 0x00010000 | Input name classification |
| Explicit DNS domain name | DS_IS_DNS_NAME | 0x00020000 | Input name classification |
| NextClosestSite | DS_TRY_NEXTCLOSEST_SITE | 0x00040000 | Site preference/fallback |
| Windows2008 minimum | DS_DIRECTORY_SERVICE_6_REQUIRED | 0x00080000 | Minimum DC service generation |
| ADWS | DS_WEB_SERVICE_REQUIRED | 0x00100000 | Require advertised ADWS |
| Windows2012 minimum | DS_DIRECTORY_SERVICE_8_REQUIRED | 0x00200000 | Minimum DC service generation |
| Windows2012R2 minimum | DS_DIRECTORY_SERVICE_9_REQUIRED | 0x00400000 | Minimum DC service generation |
| Optional SDK Windows2016 minimum | DS_DIRECTORY_SERVICE_10_REQUIRED | 0x00800000 | Extension beyond pinned cmdlet enum |

Windows2000 minimum needs the base DS-required criterion. The command's accepted-values table includes Windows2012/Windows2012R2 even though its prose lists only Windows2000/Windows2008. Capture the installed enum on each reference version. Do not infer OS support for every additional generated constant: this pin also contains `_12_REQUIRED` and `_13_REQUIRED`, whose public SDK meaning/host support is outside the established cmdlet contract. [Pinned reference](../../coverage/reference.json), [MS-NRPC locator processing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nrpc/fb8e1146-a045-4c31-98d1-c68507ad5620).

Validate native-invalid combinations before calling Windows: GC/PDC/KDC are mutually exclusive; DNS/flat input flags and DNS/flat output flags are mutually exclusive; explicit SiteName cannot accompany NextClosestSite. GC discovery expects the forest root name. NextClosestSite is ignored with PDC or flat output; the proposed API should reject those ineffective combinations rather than imply a guarantee. Do not expose ONLY_LDAP_NEEDED for DC discovery. [DsGetDcNameW](https://learn.microsoft.com/en-us/windows/win32/api/dsgetdc/nf-dsgetdc-dsgetdcnamew).

ReliableTimeService must be represented as a preference, not a hard requirement. The protocol allows fallback to an ordinary time server. NextClosestSite also eventually permits another available site. Preserve requested criteria and returned capability bits separately, and test the permitted fallback. The inventory's wording about satisfying all criteria must be interpreted with these native preference semantics; if a strict reliable-time API is later added, it needs a separate explicit postcondition. [MS-NRPC locator processing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nrpc/fb8e1146-a045-4c31-98d1-c68507ad5620).

Return an owned Go `DiscoveredController`, not a fully populated LDAP `DomainController`. Preserve the native controller name/address, address type, domain GUID/name, forest name, flags, DC site and client site. Keep optional site strings nullable. Normalize the native leading backslashes only when deriving an endpoint, and validate that endpoint independently. Address type controls interpretation; one returned address is not a complete A/AAAA inventory. Output flags distinguish GC, PDC, writable, RODC (`DS_SELECT_SECRET_DOMAIN_6_FLAG`), time service, and DNS-name format. [DOMAIN_CONTROLLER_INFOW](https://learn.microsoft.com/en-us/windows/win32/api/dsgetdc/ns-dsgetdc-domain_controller_infow).

Discovery is not authenticated LDAP or guaranteed current reachability. Bind explicitly before treating a candidate as an authenticated directory endpoint. Preserve Windows cache behavior by default; forced discovery must be caller-visible. The native call is synchronous, so observe cancellation before/after it without claiming interruption or freeing a still-active output. [DsGetDcNameW](https://learn.microsoft.com/en-us/windows/win32/api/dsgetdc/nf-dsgetdc-dsgetdcnamew).

## Credentials, current context, and explicit targets

Keep four concepts separate in the API: the machine performing discovery, the domain selected by identity/current context, the exact LDAP endpoint, and authentication credentials. Explicit credentials authenticate reads; they do not redefine LocalComputer or LoggedOnUser. When Current and Server are both supplied, the documented Domain/Forest behavior checks that the server's domain matches the chosen current domain, including for Forest. Compare stable domain identity after binding rather than comparing DNS spelling alone. [Get-ADDomain Current rules](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-addomain?view=windowsserver2025-ps), [Get-ADForest Current rules](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adforest?view=windowsserver2025-ps).

Suggested context resolution:

1. LocalComputer: `NetGetJoinInformation(nil, ...)`, require `NetSetupDomainName`, copy the returned domain name, then free its owner. Workgroup/unjoined/unknown is an actionable missing-context result; never discover the workgroup as a domain. [NetGetJoinInformation](https://learn.microsoft.com/en-us/windows/win32/api/lmjoin/nf-lmjoin-netgetjoininformation).
2. LoggedOnUser: resolve the calling security identity with `GetUserNameExW(NameDnsDomain)` and the documented resize protocol; parse the DNS domain before the backslash in its `domain.example\samName` result. Do not trust environment variables or assume a UPN suffix is the AD domain. The API follows thread impersonation and only supports SAM-compatible naming for a local account. Resolve context and bind on a consistent OS-thread/token policy; qualify service and impersonation cases before claiming exact PowerShell equivalence. [GetUserNameExW](https://learn.microsoft.com/en-us/windows/win32/api/secext/nf-secext-getusernameexw), [EXTENDED_NAME_FORMAT](https://learn.microsoft.com/en-us/windows/win32/api/secext/ne-secext-extended_name_format).
3. If no endpoint was requested, perform explicit domain discovery and then `Dial` the returned DNS host. If an endpoint was supplied, retain that endpoint and verify scope; do not silently replace it after failure. A domain name and a server name need separate constructors because their shapes can be identical. This preserves the existing [Endpoint and Client contract](../../config.go).

The DiscoverByService set has no Credential or Server parameter. Its AuthType parameter does not make `DsGetDcNameW` credential-aware. Any convenience operation that discovers and then authenticates must describe the two phases and return bind failures without selecting a different identity. Existing `Dial` already supports current/explicit Negotiate and clears the retained credential pointer. TLS/Basic acceptance remains dependent on the connection work; it must not silently downgrade or count as covered by Negotiate-only tests. [Inventory syntax](../../coverage/inventory.json), [client implementation](../../client.go), [credential research](winldap-explicit-credentials.md).

PowerShell provider-drive and pipeline defaults do not exist in Go. Proposed Go defaults should be explicit connected-endpoint selectors, and typed references should carry source identity/endpoint metadata rather than trigger implicit reconnection. Document this as an intentional difference and test it under `endpoint-and-partition`; do not quietly label a connected-domain read as LoggedOnUser parity. [Coverage contract](../coverage-guide.md).

## LDAP projections and joins

Use RootDSE naming-context values from the authenticated endpoint, not DNS-to-DN string construction. Read the domain NC, configuration NC and schema NC with explicit scopes. Keep the source endpoint on every result; topology is a replicated observation, not an atomic forest snapshot. General searches need paging and range retrieval, and joins must return partial data with an error if a required page or linked object cannot be read. The existing RootDSE decoder's copied raw values, nullable scalars, unknown-value retention and partial-error style are suitable precedents. [rootdse.go](../../rootdse.go), [native RootDSE reads](../../native_rootdse_windows.go).

Microsoft's ADWS custom-action specification is useful here as a property-mapping reference, without making ADWS the SDK transport. It lists the participating classes and attributes. [MS-ADCAP schema elements](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/ffe93276-e9e7-40f0-9f6d-106bdb6fb4a0).

### Domain and forest

| Read | Data and proposed projection |
| --- | --- |
| Domain NC root (`domainDNS`) | DN/GUID, `objectSid`, `msDS-Behavior-Version`, `msDS-AllowedDNSSuffixes`, `msDS-LogonTimeSyncInterval`, `managedBy`, `subRefs`, `wellKnownObjects`, `rIDManagerReference`, `fSMORoleOwner`. [Domain-DNS schema](https://learn.microsoft.com/en-us/windows/win32/adschema/c-domaindns) |
| `CN=Partitions,<configuration NC>` and its `crossRef` children | Domain DNS/NetBIOS names from `dnsRoot`/`nETBIOSName`, NC identity from `nCName`; distinguish domain, application, and external references using class/flags and enabled state. Domain parent relationships follow `trustParent` (and alternate-root relationships use `rootTrust`), not DNS suffix arithmetic. [Domain crossRef](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/cbb36818-4e8a-4d16-819e-f473d83973a9) |
| Partitions container (`crossRefContainer`) | Forest functional level, `uPNSuffixes`, `msDS-SPNSuffixes`, naming-master role reference. [Cross-Ref-Container schema](https://learn.microsoft.com/en-us/windows/win32/adschema/c-crossrefcontainer) |
| `CN=Sites,<configuration NC>` | Site names, servers, NTDS settings, GC candidates; map references to server DNS hosts. Complete pages and joins before declaring a complete forest topology. [MS-ADCAP schema elements](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/ffe93276-e9e7-40f0-9f6d-106bdb6fb4a0) |

[MS-ADCAP ComputersContainer](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/bf32b210-9009-4a50-8a20-18631d8e0d7e).

| RID master | Object referenced by domain root `rIDManagerReference`. [RID mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/30b11f1c-deb5-4c7e-8b38-232da9a3453b) |
| Infrastructure master | Infrastructure container of the domain NC. [Role mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/f6c6873d-c6ef-46b0-9352-42e9d2b0904e) |
| Schema master | Schema NC root. [Schema mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/de328d50-fe8f-4075-beb9-8cb897d56f0c) |

Each role value is an NTDS-settings DN; resolve its parent server and `dnsHostName`, preserving the original DN if hostname resolution fails. Retain role membership independently from reachability. Read domain/forest roles from their owning naming contexts, not from one locator's PDC flag. Missing role-owner or host attributes can legitimately yield nullable projections. A complete property checklist must also retain the reference's container fields, domain child/parent lists, writable/read-only replica lists, forest application partitions, cross-forest references, global catalogs and suffixes. Do not declare these implemented merely because the core role fields are present. The precise reference classification of disabled/external crossRefs and replica-list ordering remains a fixture comparison item; the proposed joins above are an implementation plan, not observed parity. [Domain example](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-addomain?view=windowsserver2025-ps), [Forest example](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adforest?view=windowsserver2025-ps).

### Domain controllers

Use configuration-partition `server` objects, their child `nTDSDSA` objects, and `serverReference` to the computer object as one joined DC identity. Do not enumerate just the Domain Controllers OU: its location and computer membership alone do not provide the required server/DSA identities. Resolve DN inputs by object class; GUID inputs need the correct configuration scope. For an explicit computer DN, follow the server/computer link and require a matching DSA. Host/IP identity requires a verified mapping to that same joined identity; reverse DNS alone must not select an arbitrary object. These are proposed resolver constraints informed by [MS-ADCAP's NTDS-settings input](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/3c9b9f1d-655d-43a2-a231-9ba53fdf93b8) and [schema elements](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/ffe93276-e9e7-40f0-9f6d-106bdb6fb4a0).

The server supplies its GUID/DN/hostname and site ancestry; the computer supplies SID/account state and OS attributes; the DSA supplies its GUID/DN, `invocationId`, domain/replica NC attributes, options, and read-only category. Retain these identifiers separately: invocation ID is not object GUID. Domain scope must be checked through domain-NC references, because Sites spans the forest. [Server schema](https://learn.microsoft.com/en-us/windows/win32/adschema/c-server), [nTDSDSA object](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/8ebf2419-1169-4413-88e2-12a5ad499cf5), [MS-ADCAP schema elements](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/ffe93276-e9e7-40f0-9f6d-106bdb6fb4a0).

GC configuration is `nTDSDSA.options & NTDSDSA_OPT_IS_GC` (mask `0x1`); live GC readiness is the endpoint's separate RootDSE `isGlobalCatalogReady`. RODC status follows the DSA's `objectCategory` identifying `nTDSDSARO`; do not infer it from missing permissions, missing GC status, or the computer's enabled bit. The reference may render unreadable values false; the SDK should retain presence information and document any safer typed difference. [GC mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/53a7f2e4-48f5-4e49-8475-2e363e6d9f5b), [RODC mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/cdfb7017-90d4-4453-89dd-eca6ee9d1c32), [RootDSE](../../rootdse.go).

DC partitions are the deduplicated union of `msDS-hasMasterNCs`, `msDS-hasFullReplicaNCs`, and `hasPartialReplicaNCs`. Keep replica kind internally rather than losing it during projection. FSMO role membership comes from comparing the DSA DN with the role-owner references above. [Partition mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/73fd412a-6110-4a25-a1c3-8cdb1e6738c7), [role mapping](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adcap/f6c6873d-c6ef-46b0-9352-42e9d2b0904e).

Filtering must operate over joined properties such as Site, IsGlobalCatalog and IsReadOnly, not blindly substitute their names into an LDAP filter. Partition pushdown and residual filtering are acceptable implementation choices if limits apply after semantic filtering and pagination is complete. Return partial results with a non-nil error on a missing page/join, cancellation, or inaccessible required partition. This implements the inventory's `query-scope-paging-and-filters` contract without requiring all properties to be one LDAP attribute.

### Trusts

Read `trustedDomain` objects in the selected domain's System container, located through the well-known container mapping. Proposed default projection: DN, objectGUID, name, `trustPartner`, `flatName`, `securityIdentifier`, `trustDirection`, `trustType`, `trustAttributes`, and optional encryption metadata. Keep object GUID distinct from the partner-domain SID, whose LDAP attribute is `securityIdentifier`, not `objectSid`. Preserve requested raw binary/multivalued/unknown attributes through the ordinary property mechanism. Never add secret trust authentication material to the default projection or retained test evidence. [MS-ADTS TDO attributes](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/c9efe39c-f5f9-43e9-9479-941c20d0e590).

Direction is relative to the source domain: 0 disabled, 1 inbound (partner trusts source), 2 outbound (source trusts partner), 3 bidirectional. Preserve the integer alongside names. [trustDirection](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/5026a939-44ba-47b2-99cf-386a9e674b04). Trust type is 1 downlevel, 2 AD, 3 MIT Kerberos, 4 historical DCE, and newer documented value 5 AAD; type 3 need not have a SID. Unknown values should survive decoding. [trustType](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/36565693-b5e4-4f37-b0a8-c1b12138e18e).

Preserve the full attributes bitmask. Known masks include nontransitive `0x1`, quarantined/SID-filtered `0x4`, forest-transitive `0x8`, cross-organization `0x10`, within-forest `0x20`, treat-as-external `0x40`, RC4 `0x80`, AES `0x100`, no-TGT-delegation `0x200`, and enable-TGT-delegation `0x800`. Some interpretations depend on trust type and security updates. Do not derive a universal trust-health or authorization verdict from these bits, or conflate ForestTransitive with WithinForest. Qualify PowerShell-derived properties such as SelectiveAuthentication and SIDFilteringForestAware against a real trust before promising their exact mapping. [trustAttributes](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/e9a2d23c-c31e-4a6f-88a0-6646fdb51a3c).

Two documentation ambiguities remain empirical gates: the example calls Filter `*` forest-wide, while TDOs are stored per domain; and partner-name identity appears in an example but not the Identity parameter list. Query a root and child domain that have different TDOs, then run all four parameter sets on explicit endpoints. Define the Go default as selected-domain scope until observed reference behavior justifies anything broader; any forest traversal must be an explicit operation reporting unreachable domains. [Get-ADTrust](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adtrust?view=windowsserver2025-ps), [TDO placement](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/c9efe39c-f5f9-43e9-9479-941c20d0e590).

`DsEnumerateDomainTrustsW` is available but is not the primary Get-ADTrust implementation: it has no explicit credential input or property/filter projection and may return a member's cached data. Its domain relationships can include entries that are not one-for-one TDO query results. It can be a supplementary cross-check, with its own documented semantics. [Native enumeration](https://learn.microsoft.com/en-us/windows/win32/api/dsgetdc/nf-dsgetdc-dsenumeratedomaintrustsw).

## Version and capability guards

Keep OS version, DC service generation, schema version, domain functional level, and forest functional level distinct. `msDS-Behavior-Version` on the DSA describes the DC's supported level; Domain/Forest levels are read from their own objects. The documented DSA level is 7 for Server 2016/2019/2022 and 10 for Server 2025. A Server 2025 DC may serve a forest whose configured level is lower. Preserve unknown numeric levels rather than rejecting a future server. [MS-ADTS DC functional levels](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/8f0d9838-d9f2-44b8-b018-b41b62c0580c).

Server 2025 changes NetBIOS-based discovery policy; short names can still be mapped to DNS names. Test DNS/NetBIOS inputs separately and record Netlogon policy, rather than changing process or machine policy to force a pass. Host capabilities matter independently from the remote DC's OS. [Microsoft DC Locator guidance](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/dc-locator).

For Domain, Forest, and DC LDAP operations, inspect supportedCapabilities and required naming contexts before projecting AD DS semantics. Recognize AD LDS explicitly and return a typed directory-capability error. Do not classify missing defaultNamingContext alone as AD LDS. The existing RootDSE report explains why missing/denied data is not proof of absent schema or capability. [Coverage applicability](../../coverage/inventory.json), [RootDSE capability research](winldap-connection.md).

**Get-ADTrust requires a separate AD LDS decision.** Its documentation mentions LDS in generic Server help and does not establish full operational support; the inventory correctly retains `unverified`. Do not introduce a blanket DS-only guard and call the LDS requirement resolved. Required reference probe: on a controlled LDS instance with recorded schema, capabilities, default NC and nondefault port, run Filter `*`, LDAPFilter `(objectClass=trustedDomain)`, DN/GUID identity, selected/wildcard properties, and each accepted InputObject type. Record return type, zero versus error, native/error category, and explicit-server retention for current/explicit Negotiate and any supported TLS/Basic mode. Inspect whether `trustedDomain` and required attributes actually exist in that schema. If possible under supported provisioning, compare a representative object; schema absence or an empty search does not prove positive parity. Native LDAP reads and the PowerShell cmdlet may differ. Retain unverified status or document an intentional unsupported mode until these observations justify a narrower contract. [Trust documentation](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adtrust?view=windowsserver2025-ps), [inventory](../../coverage/inventory.json).

## Proposed Go surface

These are design signatures, not implemented names. Reuse shared identity/filter/search abstractions when they land rather than adding an incompatible second query language.

```go
// Locator is independent of an authenticated Client.
func DiscoverDomainController(ctx context.Context, o DiscoveryOptions) (DiscoveredController, error)
func CurrentDomain(ctx context.Context, mode CurrentMode) (DomainReference, error)

func (c *Client) Directory() *DirectoryService
func (d *DirectoryService) Domain(ctx context.Context, s DomainSelection) (Domain, error)
func (d *DirectoryService) Forest(ctx context.Context, s ForestSelection) (Forest, error)
func (d *DirectoryService) DomainController(ctx context.Context, id DCIdentity) (DomainController, error)
func (d *DirectoryService) DomainControllers(ctx context.Context, q DCQuery) (DCResults, error)
func (d *DirectoryService) Trust(ctx context.Context, id TrustIdentity, p PropertySelection) (Trust, error)
func (d *DirectoryService) Trusts(ctx context.Context, q TrustQuery) (TrustResults, error)
func (d *DirectoryService) TrustsFor(ctx context.Context, ref DirectoryReference, p PropertySelection) (TrustResults, error)
```

Recommended shape and validation:

- `DiscoveryOptions`: tagged DNS/NetBIOS domain selector, optional site, hard service requirements, `PreferReliableTimeService`, minimum DC service version, writable, avoid-self, next-closest-site, and force-discover. Reject unsupported service combinations; do not accept raw flags as the primary API. The result preserves requested criteria, returned flags, and a separately validated endpoint candidate.
- `DomainSelection`/`ForestSelection`: exactly one of connected endpoint, explicit typed identity, or Current(LocalComputer/LoggedOnUser). No contradictory selectors. Current selectors verify endpoint domain membership as described above.
- `DCIdentity`: explicit constructors for each supported form, separating server GUID and DSA GUID where possible. Require source/scope validation when reusing returned references. Empty identity can have an explicit `ConnectedController` equivalent rather than accidental discovery.
- `DCQuery`: typed expression filters with scoped semantic properties, bounded paging, caller result limit and cancellation. `TrustQuery` additionally accepts a separately tagged LDAP filter. Neither silently truncates results or converts a partial collection to success.
- Result structs: optional scalar pointers, typed identifiers, raw integer levels/bitmasks, source endpoint, requested-property metadata and copied raw attributes. Preserve unloaded versus requested-but-not-returned values; a missing value does not prove absent schema. A result plus non-nil error is partial, following RootDSE precedent.
- `TrustsFor`: accepts typed domain/forest/object references corresponding to InputObject; avoid an `any` argument that silently accepts unsupported types. The precise reference mapping is gated by the real fixture probes below.

This split makes locator-only progress reviewable while leaving DomainController identity/filter and all topology/trust coverage explicitly unfinished. The service should expose connection capability errors rather than silently constructing a new client or retaining passwords for arbitrary cross-domain traversal.
