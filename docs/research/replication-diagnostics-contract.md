# Replication diagnostics contracts

Research date: 2026-11-12. Scope: issue #36, `Get-ADReplicationPartnerMetadata`, `Get-ADReplicationFailure`, and `Get-ADReplicationQueueOperation`. This is contract research and inspection of the pinned dependency, not implementation or live-server evidence. No directory, credential, VM, or Git mutations were performed.

## Command behavior and scope

Partner metadata supports inbound, outbound, or both directions; the examples establish inbound/default naming context as the default. Partition selection includes an explicit NC, `Schema`, `Configuration`, and `*` for all hosted partitions. Server, site, domain, and forest scopes expand to the relevant servers, with an enumeration server separate from the individual diagnostic targets. The current `Partition` parameter prose mistakenly repeats authentication text; use the description/examples for the documented partition behavior. [Get-ADReplicationPartnerMetadata, Windows Server 2025](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adreplicationpartnermetadata?view=windowsserver2025-ps).

Failure reporting covers current failures on a DC or AD LDS instance and supports server/site/domain/forest targets. Both connection and link failures must survive the mapping. It is not equivalent to selecting neighbor records whose last-sync status is nonzero. [Get-ADReplicationFailure, Windows Server 2025](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adreplicationfailure?view=windowsserver2025-ps), [DS_REPL_INFO_TYPE](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ne-ntdsapi-ds_repl_info_type).

The queue command itself takes one server, plus partition/filter selection; broader queue scopes would be an SDK aggregation feature. It reports pending replication work, with individual work items referring to a server/partition pair. The command permits AD LDS endpoints. Its generic partition help says an LDS instance without a configured default NC has no default partition; do not silently substitute its configuration NC. Its `Identity` references are inconsistent with the actual syntax. [Get-ADReplicationQueueOperation, Windows Server 2025](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-adreplicationqueueoperation?view=windowsserver2025-ps).

**Implementation inference:** scope expansion should preserve target identity, per-target failures, and partial results. A forest query cannot be implemented as a single DC's local replication query. AD LDS instances support diagnostics, but a configuration set is not an AD DS domain or forest; do not invent those scopes for LDS.

## Complete native and LDAP mapping

| Information | Documented native type/result | Documented LDAP equivalent |
| --- | --- | --- |
| Inbound partners | `DS_REPL_INFO_NEIGHBORS` (0), `DS_REPL_NEIGHBORSW` array | RootDSE `msDS-ReplAllInboundNeighbors`; NC-root `msDS-NCReplInboundNeighbors` |
| Outbound partners | No outbound member in public Win32 `DS_REPL_INFO_TYPE`; MS-DRSR separately defines `DS_REPL_INFO_REPSTO` | RootDSE `msDS-ReplAllOutboundNeighbors`; NC-root `msDS-NCReplOutboundNeighbors` |
| Connection failures | `DS_REPL_INFO_KCC_DSA_CONNECT_FAILURES` (3), `DS_REPL_KCC_DSA_FAILURESW` array | RootDSE `msDS-ReplConnectionFailures` |
| Link failures | `DS_REPL_INFO_KCC_DSA_LINK_FAILURES` (4), same array type | RootDSE `msDS-ReplLinkFailures` |
| Current/queued operations | `DS_REPL_INFO_PENDING_OPS` (5), `DS_REPL_PENDING_OPSW` | RootDSE `msDS-ReplPendingOps`, one `DS_REPL_OPW` representation per value |

The four mappings in the supplied RootDSE reference are explicitly equivalent to `IDL_DRSGetReplInfo` data. The published Win32 enum covers inbound neighbors, both failure types, and pending operations. [MS-ADTS §3.1.1.3.2.28](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/b4a0b2bf-95f9-40b4-9301-834ccadea40c), [Win32 enum](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ne-ntdsapi-ds_repl_info_type).

Outbound is documented separately: `msDS-ReplAllOutboundNeighbors` represents `repsTo` values across NC replicas with the same neighbor XML/blob representation as inbound. This is §3.1.1.3.2.29, immediately after the supplied four-attribute section. [Microsoft MS-ADTS PDF, 2024-06-10, p. 182](https://winprotocoldoc.z19.web.core.windows.net/MS-ADTS/%5BMS-ADTS%5D-240610.pdf#page=182), [current MS-DRSR LDAP relationship](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/0597aff6-0177-4d52-99f2-14a5441bc3c1).

The per-NC equivalents are also fully documented. Reading inbound neighbors from a non-NC-root object returns no value; outbound applies the analogous representation to `repsTo`. [MS-ADTS NC inbound representation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/21ea8133-4947-4409-bca8-4239723d3e6a), [MS-ADTS NC outbound representation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/56907a09-bd4c-4ee2-9392-0339d9b172fd).

MS-DRSR's reply union reserves `0xFFFFFFFE` for `pRepsTo`. That protocol fact does **not** document passing an invented enum member through `DsReplicaGetInfo2W` or freeing it through the public Win32 wrapper. Prefer the documented LDAP route for outbound rather than claiming unsupported Win32 ABI parity. [DRS_MSG_GETREPLINFO_REPLY](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/374665d4-0c2f-4f0c-9866-d6b0855ede60).

## Fields, timestamps, statuses, and missing information

Inbound neighbor data preserves NC DN/GUID, partner DSA DN/GUID/address, partner invocation ID, transport DN/GUID, replica flags, two signed 64-bit USNs, last-success/last-attempt times, native last-result code, and consecutive failures. The transport DN can be NULL for RPC/IP. Zero last-success/attempt FILETIME means never completed/attempted, not an event in 1601. The object GUID and invocation ID are distinct identifiers. [DS_REPL_NEIGHBORW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ns-ntdsapi-ds_repl_neighborw).

Outbound times, last-result code, and failure count describe **sending replication notifications**, not completion of the destination's replication cycle. `repsTo` does not use its invocation-ID, transport-ID, or USN-vector fields. Preserve that distinction in direction-aware metadata; do not manufacture inbound semantics or populate those fields by reversing an inbound record. [REPS_TO](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/b422aa87-7d07-4527-b070-c5d719696c43).

A partition-specific neighbor request intentionally returns a NULL NC GUID; all-NC requests can return it. Outbound construction does not assign inbound invocation-ID/USN/transport fields. This missing data is request/direction dependent, not evidence of an old server. [MS-DRSR server behavior](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/caa21197-11be-4efe-b9ae-35477ee68c8c).

Failure records preserve source DSA DN/GUID, timestamp, consecutive count, and native result. The field named `ftimeFirstFailure` means first failure for **connection** failures but **last successful replication** for **link** failures. A failure record's `dwLastResult == ERROR_SUCCESS` means the particular error is unavailable; it does not remove the failure. Expose the category and timestamp meaning. [DS_REPL_KCC_DSA_FAILUREW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ns-ntdsapi-ds_repl_kcc_dsa_failurew).

Queue entries preserve enqueue time, operation serial, priority, operation type, raw options, NC DN/GUID, and partner DSA DN/GUID/address. DSA DN/address may be NULL. Serial numbers are only unique within a machine startup. Higher numeric priority runs first; options have different meanings for sync/add/delete/modify/update-refs. Unknown numeric values should remain representable. [DS_REPL_OPW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ns-ntdsapi-ds_repl_opw).

The native queue container additionally supplies current-operation start time and array count; its first entry is the executing operation. Per-operation RootDSE values do not contain that container timestamp, and LDAP multivalue ordering should not be elevated into a current-operation guarantee. [DS_REPL_PENDING_OPSW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/ns-ntdsapi-ds_repl_pending_opsw).

`msDS-ReplQueueStatistics` separately exposes current-operation start, count, and oldest-operation times. Its documented no-operation XML timestamp is `1601-01-01T00:00:00Z`. It can supplement LDAP queue records, but separate reads are not an atomic snapshot. [MS-ADTS queue statistics](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/c0793fe4-5ba8-48c8-b284-525d533ed49f).

## XML, enumeration, and permissions

The outbound XML root is `DS_REPL_NEIGHBOR`; the `W` suffix belongs to the
native structure and the binary blob name, not the XML element. A Server 2025
LDAP observation also returned one terminal NUL byte after the XML newline.
The SDK strips only that final byte for parsing, retaining the raw value and
rejecting interior NULs or trailing content. [MS-ADTS outbound representation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/56907a09-bd4c-4ee2-9392-0339d9b172fd).

In the same lab, PowerShell's `-Partition '*'` returned the domain, configuration
and schema NCs but omitted both DNS application NCs. The reference collector
therefore passes an explicit list from the target server's RootDSE naming
contexts. The native all-NC result remains unchanged; parity must include the
application partitions rather than discard those observations.

Unqualified replication attributes return XML with the structure name as parent and native field names/order as children. Integers are decimal strings, GUIDs use GUIDStrings, and FILETIMEs become UTC XML dateTime values. `;binary` requests a blob whose string fields are offsets to embedded NUL-terminated UTF-16. The cited contract does not specify a universal null-string XML spelling; omitted/empty optional elements must not become malformed mandatory data automatically. [MS-ADTS RootDSE encoding](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/b4a0b2bf-95f9-40b4-9301-834ccadea40c), [NC attribute encoding](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/21ea8133-4947-4409-bca8-4239723d3e6a).

`DsReplicaGetInfo2W` takes an NC DN for neighbors and NULL object for failures/queue. The source GUID filter applies only to inbound neighbors. For these diagnostics, use NULL attribute/value, flags zero, and enumeration context zero. The documented 1000-entry paging protocol applies to cursor-v2/v3 and attribute-value metadata types, **not** these three diagnostic result types. Their arrays have counts rather than continuation fields. Other supported paged types start at zero and finish at `0xFFFFFFFF`; passing that terminal context returns `ERROR_NO_MORE_ITEMS`. Native errors are Win32/RPC status values. [DsReplicaGetInfo2W](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsreplicagetinfo2w).

LDAP entry paging does not paginate values of one diagnostic attribute. Honor returned `;range=low-high` names, including the empty unqualified attribute that can accompany a populated range; continue until the returned upper bound is `*`. Ordering is stable only on the same connection while values remain unchanged. Therefore preserve incomplete/concurrent-read possibilities instead of silently accepting a truncated value set. [MS-ADTS range retrieval](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/e27b48db-6f82-44cd-9038-2e54f790cc1f).

NC-neighbor reads require read-property access on `repsFrom`/`repsTo`, or the relevant manage/monitor-topology control access right. Crucially, denied extended access makes an LDAP value appear nonexistent. **An absent constructed attribute cannot by itself distinguish no partners, access denial, or unavailable data.** Capability checks establish support, not permission or an empty result. [MS-ADTS extended access checks](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/e6685d31-5d87-42d0-8a5f-e55d337f47cd).

RPC failure/queue reads require manage-topology or monitor-topology access on the default NC. Neighbor reads also allow the corresponding property access. The server returns `ERROR_DS_DRA_ACCESS_DENIED` when access fails. A successful native counted result can establish zero entries; an LDAP omission cannot supply that stronger claim unaided. [MS-DRSR server access checks](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-drsr/caa21197-11be-4efe-b9ae-35477ee68c8c).

**Implementation inference:** expose per-category/partition completeness and missing-information reasons. Distinguish observed records, confirmed empty native responses, omitted LDAP data, unsupported capabilities, invalid XML, and actual transport/authentication failures. Do not label every omission unsupported or return it as a confirmed healthy result. Preserve unknown elements/raw values where practical; the cited specification does not promise a richer version-specific neighbor type.

## Platform and LDS applicability

The RootDSE support table lists inbound/outbound neighbors, both failures, pending operations, and queue statistics for Windows Server 2016, 2019, 2022, and 2025, including the applicable AD LDS columns. They are operational attributes and must be requested explicitly. `msDS-SupportedRootDSEAttributes` is not listed for 2016 but is listed in later applicable columns, so requiring it would incorrectly reject 2016. RootDSE attributes are not schema entries. These are support contracts, not evidence that the SDK has passed that server matrix. [MS-ADTS RootDSE support table](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/96f7b086-1ca3-4764-9a08-33f8f7a543db).

`DsBindByInstanceW` explicitly supports AD DS and AD LDS. For LDS, supply the computer DNS name and either the LDAP port as `Annotation` or the instance's nTDSDSA object GUID; `DnsDomainName` is NULL. A GUID is preferred on hosts with several instances. This is RPC binding identified by an LDAP instance port, not an LDAPS transport selection. The binding accepts a credential handle and optional SPN; its documented flags include Kerberos-only behavior and delegation. Diagnostics do not justify enabling delegation. [DsBindByInstanceW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsbindbyinstancew).

`DsBindWithCredW` uses the calling thread's credentials when its credential handle is NULL. Its documentation requires `DnsDomainName` for Kerberos authentication. Explicit credentials come from `DsMakePasswordCredentialsW`; unbind before freeing credentials. The native RPC contract does not implement the PowerShell/LDAP Basic-over-SSL mode, so that transport/authentication policy must not be silently translated into a weaker RPC bind. [DsBindWithCredW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsbindwithcredw), [DsMakePasswordCredentialsW](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsmakepasswordcredentialsw).

`DsBindingSetTimeout` sets a seconds-based timeout for RPC calls using an existing binding; it does not document a deadline for the initial bind or arbitrary Go context cancellation. Copy returned data before calling `DsReplicaFreeInfo` with the same info type used to allocate it, then unbind and free credentials in that order. [DsBindingSetTimeout](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsbindingsettimeout), [DsReplicaFreeInfo](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsreplicafreeinfo).

**Credential representation boundary:** generic RPC documents `RPC_AUTH_IDENTITY_HANDLE` as a provider-specific pointer and uses `SEC_WINNT_AUTH_IDENTITY` for NTLM, Kerberos, and Negotiate; it recommends retaining the identity through binding lifetime. The NTDSAPI-specific pages instead document creation with `DsMakePasswordCredentials` and release after unbinding. No explicit NTDSAPI contract accepting a caller-owned `SEC_WINNT_AUTH_IDENTITY_W` was found, nor evidence proving a different private layout. Direct substitution is therefore an inference, not a verified workaround. Never pass caller-owned memory to `DsFreePasswordCredentials`, which releases the maker's allocations. [RPC credentials](https://learn.microsoft.com/en-us/windows/win32/rpc/client-authentication-credentials), [RpcBindingSetAuthInfoExA](https://learn.microsoft.com/en-us/windows/win32/api/rpcdce/nf-rpcdce-rpcbindingsetauthinfoexa), [DsFreePasswordCredentials](https://learn.microsoft.com/en-us/windows/win32/api/ntdsapi/nf-ntdsapi-dsfreepasswordcredentials).

[Pinned functions](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/bindings/win32/networking/activedirectory/activedirectory_functions.go).

[Pinned enums](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/bindings/win32/networking/activedirectory/activedirectory_enums.go), [pinned structures](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/bindings/win32/networking/activedirectory/activedirectory_structs.go).
- Generated ABI expectations cover both architectures: neighbor record 144 bytes, failure record 40, operation record 80; one-element containers are respectively 152, 48, and 96. The `[1]` tail is a flexible-array declaration, not a one-result limit. These expectations were inspected, not executed here. [Pinned ABI test](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/acceptance/abi/abi_networking_activedirectory_test.go).
- `DsMakePasswordCredentials` takes `*string` and calls `UTF16PtrOrNil`, producing a temporary UTF-16 password allocation the caller cannot wipe. The ANSI wrapper accepts pointers, but does not preserve general Unicode credential equivalence. If the SDK requires mutable-buffer erasure, use the existing authenticated LDAP path or fix the upstream generator's Unicode password input rather than silently weakening that lifetime policy. [Pinned functions](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/bindings/win32/networking/activedirectory/activedirectory_functions.go), [pinned string conversion](https://github.com/deploymenttheory/go-bindings-win32/blob/fa6dc8c4593e/bindings/runtime/win32/runtime.go).

The documented native inbound/failure/queue APIs and result types are present, with the explicit-password buffer limitation above. Outbound can use the documented constructed LDAP attribute without raw syscall shims or hand-written generated types. Remaining implementation choices must preserve omission ambiguity, all requested directions/scopes, raw native values, and version/direction-dependent missing information. Windows amd64/arm64 compilation and live AD DS/LDS matrix verification remain separate acceptance work.
